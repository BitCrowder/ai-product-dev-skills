# 规格转实施计划模板

路径、命令和既有接口只可引用已读或用户提供的证据。没有仓库证据时，将路径写为 `[未知，待仓库证据]`，把职责写为候选，并列出搜索/阅读动作。

|---|---|---|---|

| 可验收行为 | | | |

2. 失败、重试、恢复和边界状态：

## 5. 接口契约
| ID | 类型与契约定义 owner | 运行时角色 | 触发 | Consumes | Produces/副作用 | 失败/权限/幂等 | 兼容与契约测试 |
|---|---|---|---|---|---|---|---|
| I-01 | 请求/结果；定义 owner： | runtime producer：；consumer： | | | | | |
| I-02 | 数据 schema；定义 owner： | runtime producer：；sink： | | | 类型化数据 | | |
| I-03 | capability；定义 owner： | provider：；consumer： | | `I-02` | 确认/失败结果 | | |

- 依赖：`T-01 -> T-02`（原因：<接口/schema/决策/环境>）。事件模式：`T-02(schema) -> T-03(capability) -> T-04(runtime caller)`。

| 状态 | 目的 | 工作目录 | 前提 | 命令或方法 | 期望观察 | 证据/阻断原因 |
|---|---|---|---|---|---|
| [未运行] | | | | | | |

## 12. 风险、阻塞项、owner 与决策时点
| ID | 风险或阻塞 | 影响 | 缓解/判定动作 | owner | 最晚时点 |

- 首个可执行任务及其前提：

`[未运行]` 命令只能表达计划，不得填退出码或“通过”。已运行的命令应追加实际时间、退出码、脱敏关键输出和可定位记录；静态脚本或 CI 配置只能证明命令存在。
