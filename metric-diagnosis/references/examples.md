# 产品指标诊断示例

## 场景一：完整异常，注册转化下降 15%

输入：`注册转化率本周下降 15%，帮我找原因。`

合格处理：

```markdown
先确认“15%”的含义：是百分点还是相对变化？请提供两期的注册完成数/合格访问数、事件定义、去重键、时区、当前数据截至时间，以及是否按相同星期、活动和数据成熟度比较。

数据质量门：核对 `signup_completed` 与 `eligible_visit` 的埋点版本、延迟、回填、重复、机器人过滤和 join 匹配；任一项失败时只处理数据质量。

变化账本示例：若从 4,200/10,000（42%）到 3,960/12,000（33%），则为 -240 个完成、+2,000 个合格访问、-9 个百分点、约 -21.4% 相对变化。不能称为“下降 15%”，且分母增长可能是主要信号。

分解顺序：按渠道、平台、版本和新老用户比较各群的分子/分母与流量构成，再检查漏斗中访问 -> 开始注册 -> 提交 -> 完成的起始变点。发布日志只作为候选解释：核实实际暴露时间和版本覆盖，再用未暴露平台、稳定渠道或实验设计验证。
```

结论边界：在口径、完整性和可比性通过前，不能给出业务原因；即使变点与发布接近，也只可称为待验证关联。

## 场景二：信息不足，只有一张截图

输入：`只有这张截图，注册转化从 42% 变成 33%，告诉我发生了什么。`

合格处理：

```markdown
[截图读数] 图中似乎显示 42% 与 33%；[未知] 指标公式、分子/分母、样本量、时间窗、时区、筛选器、用户/会话去重、数据截至时间、延迟/回填和分群。

因此不能解释“发生了什么”，也不能判断是否真实下降。请提供仪表盘链接或导出、指标元数据、两期分子/分母、事件版本和数据新鲜度；随后按相同数据成熟度重算变化账本，并检查渠道、平台、版本和漏斗。

当前可执行动作：保留截图为线索；在监控中标记待核异常；不发布根因、归因或修复收益结论。
```

结论边界：截图只能支持取数请求，不能支持比例、季节性、分母变化、分群或因果结论。

## 场景三：边界请求，要求直接归因

输入：`新功能上线后转化下降，而且相关性很强，直接归因给这个功能。`

合格处理：

```markdown
不能将相关性或时间相邻直接写成因果。先确认数据质量、变点日期、功能实际暴露开始、版本/平台覆盖和回滚；同时列出渠道构成、价格/投放、性能事故、节假日和埋点变化等竞争解释。

[关联] 若下降只出现在已暴露版本，且变点与暴露开始一致，发布假设提高验证优先级；[因果待证] 仍需要未暴露对照、随机实验，或说明处理定义、干预前趋势、并行变化、选择偏差和稳健性检查的准实验设计。

行动：先做可逆缓解（如关闭功能或灰度回退）时，记录暴露与结果并设置护栏；若无可用对照或设计不满足，结论保持“与发布同时发生的关联”，不能用于追责或承诺长期收益。
```

结论边界：直接归因被拒绝，但发布仍作为有明确验证路径的候选假设保留。
