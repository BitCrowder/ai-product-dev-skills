# 产品指标诊断使用说明

## 何时调用

在指标变化需要支持排查、发布决策、风险缓解、继续观察或实验设计时调用。先说明要做什么决定，不要只问“为什么跌了”。

## 最小输入包

未知项可以留空，但必须标为 `[未知]`：

```text
要支持的决定、负责人和截止时间：
指标业务含义、公式、分子/分母、分析单位、去重、事件时间、时区和归因：
当前/基线窗口、两期分子/分母、数据截至时间、季节性或可比日历：
数据源、仪表盘/查询/埋点版本、延迟/SLA、回填、采样和已知质量问题：
分群字段、漏斗步骤、流量构成、用户或会话粒度：
发布、实验、价格、投放、性能事故和外部事件日志：
可逆缓解、风险约束和不能接受的错误结论：
```

## 推荐执行顺序

1. 先固定口径和数据截至时间，分别记录截图读数、原始数据和推断；没有公式或分子/分母时先取数。
2. 运行完整性、延迟、回填、版本、筛选、时区和可比日历检查。当前与基线不具相同成熟度时比较同龄数据或等待。
3. 用两期分子/分母写变化账本：绝对人数、百分点和相对变化同时报告，并检查分母、流量构成和资格变化。
4. 按渠道、平台、版本、地区和生命周期拆分，沿漏斗定位起点；再用变点和实际暴露日志建立发布候选关联。
5. 以竞争假设、支持/削弱信号和查询规格安排验证；只有能说明对照与混杂的设计才讨论因果。

## 何时暂停并追问

出现下列任一情况时，不直接解释业务或指向发布：

- 只有截图，或缺少公式、分子/分母、窗口、时区、去重、数据截至时间或筛选条件。
- 当前数据尚在延迟窗口，或存在未解释的缺失、重复、回填、采样、join、埋点或 SQL 版本变更。
- 基线没有匹配星期、季节、活动、产品可用性或数据成熟度，且被要求比较自然周环比。
- 只有总指标却被要求说明某一分群、漏斗环节或发布的影响。
- 仅因相关性、时间先后或“发布后下降”就被要求作因果归因、追责或承诺修复收益。

## 交付解读

- `[观察]` 是经口径和质量门确认的读数；`[关联]` 是共同变化；`[假设]` 是可被削弱的解释；`[因果待证]` 尚缺反事实；`[未知]` 不能用低置信度掩盖。
- `百分点变化` 用于两个比率相减；`相对变化` 用于相对基线的变化；两者都不解释分子和分母为何变化。
- `发布关联` 可以决定先查什么，不能单独决定根因或责任。
- 数据质量失败时，合格交付是暂停业务归因、修复/重算和重新验证条件，而不是凑出一个“最可能原因”。

完整字段见 `templates.md`，交付前使用 `checklists.md`，三种压力场景见 `examples.md`。
