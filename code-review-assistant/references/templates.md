# 证据驱动代码审查模板

## 1. 审查卡与需求/契约对照

```markdown
# 审查卡：<PR、diff 或文件集合>
- 审查范围：<路径、完整 diff/片段、base/head>
- 原始请求与目标：<链接或原文>
- [事实]：<可定位需求、代码、测试、日志或 diff 证据>
- [推断]：<依据；反证条件或验证动作>
- [未知]：<缺失信息；它阻断的判断>
- 已读上下文：<定义、调用方、错误路径、状态/数据流、测试>
- 停止条件：<缺完整 diff、消费者、契约或运行资料时结论的边界>

## 需求/契约对照
| RC-ID | 需求或公开契约 | 变更与相邻上下文 | 证据定位 | 状态：满足/风险/未知 | 备注或下一步 |
|---|---|---|---|---|---|
| RC-01 | <可观察行为> | <路径/符号> | <diff hunk、行号、测试> | <状态> | <不适用依据或问题> |
```

## 2. 发现、缺口与结论

```markdown
## 审查发现

### F-01 [P1 高] <可验证的问题标题>
- 置信度：高 / 中 / 低；<证据为何足够，或尚缺什么>
- 精确定位：`<路径>:<起止行>`；<必要时列相邻调用方/测试路径>
- 触发条件：<角色、前置状态、输入、事件顺序、规模或环境>
- 影响：<用户、数据、安全、兼容、可用性或成本后果；范围与可恢复性>
- 证据：<需求/契约 RC-ID、diff/代码行、相邻行为、测试或日志>
- 最小修复方向：<改变何处、保持什么不变量、补什么公开行为验证>

## 审查覆盖与测试缺口
| 风险面 | 已检查范围与证据 | 结论 | 缺口/建议验证 | owner |
|---|---|---|---|---|
| 正确性与回归 | <路径、测试、契约> | <已发现/未见证据/未知> | <F-* 或 GAP-*> | <角色> |
| 数据与安全 |  |  |  |  |
| 权限 |  |  |  |  |
| 并发与状态 |  |  |  |  |
| 兼容性 |  |  |  |  |
| 性能与资源 |  |  |  |  |
| 测试质量 |  |  |  |  |

## 信息缺口
| GAP-ID | 缺失材料或无法验证的边界 | 阻断的结论 | 最小补充/验证动作 | 残余风险 |
|---|---|---|---|---|
| GAP-01 | <完整 diff、需求、消费者、测试或环境> | <不能判断什么> | <路径、命令或提问> | <影响范围> |

## 结论
- 状态：通过 / 有条件通过 / 不通过
- 发现摘要：<引用 F-*；无发现时写“已读范围内未发现有证据的缺陷”>
- 审查范围与未读范围：<base/head、路径、相邻上下文>
- 已运行/未运行验证：<命令、环境、结果或 GAP-*；不以计划冒充结果>
- 合并前动作与残余风险：<必须修复项、owner、恢复条件>
- 可选正面观察：<只描述已证实事实；不替代发现或缺口>
```

`F-*` 必须同时有严重度、置信度、精确路径行号、触发条件、影响、证据和最小修复方向。证据不足时使用 `GAP-*`，不要把风格偏好或假设写成缺陷。
