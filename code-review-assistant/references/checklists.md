# 证据驱动代码审查检查清单

## 输入、范围与契约

- [ ] 已记录 PR/diff、base/head、路径范围、需求/验收、非目标与已知发布风险。
- [ ] `[事实]`、`[推断]`、`[未知]` 分开；每个未知说明它阻断的结论。
- [ ] 已审阅完整可得 diff，包括删除、重命名、配置、迁移、依赖和测试变化。
- [ ] 高风险改动已读取相邻定义、调用方/消费者、错误路径、状态/数据流及测试。
- [ ] 每项需求或公开契约都有 `RC-*` 对照，或有明确的未知/不适用依据。

## 风险面与正确性

- [ ] 主路径、边界/空值、错误、取消、回退和未受影响对照已检查。
- [ ] 数据创建、更新、删除、事务、审计、敏感信息和外部副作用的顺序可解释。
- [ ] 身份、角色、租户/资源归属、默认允许与拒绝路径已检查。
- [ ] 并发、重试、幂等、缓存、超时、乱序事件和状态转换有结论或 `GAP-*`。
- [ ] API/schema、默认值、迁移、存量数据、旧客户端/消费者和版本窗口有兼容结论。
- [ ] 热路径、查询数量、集合上界、阻塞 I/O、内存/连接释放和性能预算有证据或缺口。

## 发现与误报控制

- [ ] 每个 `F-*` 有违反的需求/契约/不变量、精确路径行号和可复现触发条件。
- [ ] 每个 `F-*` 包含影响、影响范围/可恢复性、代码/测试证据、置信度与最小修复方向。
- [ ] 严重度按影响、触发概率、可恢复性和暴露范围排序；纯风格/偏好没有标为 P3 缺陷。
- [ ] 已检查相邻保护、不可达条件、显式非目标和项目约定，排除误报。
- [ ] 证据不足的候选已降为 `GAP-*` 或澄清问题，未用低置信度掩盖猜测。

## 测试、交接与最终判定

- [ ] 测试覆盖触发条件与公开行为；不只断言私有实现、整页快照或无业务意义的 mock 次数。
- [ ] 正确性、数据/安全、权限、并发/状态、兼容、性能和测试质量均有结论或不适用依据。
- [ ] 未运行测试、环境限制、未读消费者与外部依赖均已列为 `GAP-*`，带 owner 和下一步。
- [ ] **通过：** 没有未处理 `F-*`，审查范围充分，高风险面有证据且无阻断缺口。
- [ ] **有条件通过：** 没有阻断发现，但存在明确披露的 `GAP-*`；其影响、owner 与恢复条件可接受。
- [ ] **不通过：** 存在 P0/P1，或审查范围/契约/验证缺失使高影响变更无法安全判断。
