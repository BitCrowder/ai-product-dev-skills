# 代码库入门导航使用说明

## 调用顺序

先给出要作出的决定，而不是泛称“读懂仓库”。例如：“为新增账单校验找到 API 入口、数据写入和回归测试；不审查前端页面。”再提供仓库路径、允许执行的命令、时间预算和已知线索。

1. 建立任务卡：写目标、非目标、入口线索、阅读预算和停止条件。
2. 选择深度：局部功能走一条调用链；无法启动先定位一个阻断前提；完整 Web 仓库只覆盖关键运行、数据和测试面。
3. 按 `SKILL.md` 的工作流收集路径、配置和测试证据，不读生成物、依赖目录或无关历史。
4. 用模板输出 13 项，命令统一标为 `[已运行-通过]`、`[已运行-失败]` 或 `[未运行]`。
5. 用清单复核，最后给出一条有目的、可停止的下一步阅读顺序。

## 阅读预算选择

| 情况 | 初始预算 | 最小阅读集合 | 停止信号 |
|---|---:|---|---|
| 只改局部功能 | `15-30` 分钟 | 任务入口、直接调用链、契约、最近测试、相关配置 | 可定位改动与回归测试，或发现必须扩展的跨边界 |
| 没文档/无法启动 | `20-40` 分钟 | 清单、锁文件、脚本、配置样例、容器/CI、启动入口 | 找到第一个阻断前提并保留失败证据 |
| 完整 Web 仓库 | `45-90` 分钟 | 工作区、入口、路由、服务组合根、存储、配置、测试、CI | 关键路径与运行/测试面均有可定位证据 |

预算不是承诺“读完”。耗尽后先输出已知、推测、未知和阻断点；只有当前决定无法继续时才说明为何扩展。

## 命令与证据纪律

- 运行前记录目的、工作目录和前提；运行后记录完整命令、执行时间、状态、退出码、脱敏关键输出与可定位证据。
- `[已运行-通过]` 和 `[已运行-失败]` 都必须有可定位证据：日志路径、终端记录标识，或 CI URL 加 job step。没有证据定位就降为 `[未运行]` 或补做记录，不能凭记忆写结果。
- `[未运行]` 只能是建议命令或静态发现；只填写计划工作目录和阻断原因。没有权限、依赖、凭据或时间时写出原因，执行时间、退出码、关键输出和证据定位一律写“未运行，不填”。
- `[已运行-失败]` 记录首次可复现的失败，不重复试错；下一步先读取能解释该缺失的配置、容器或 CI 文件。
- 每个架构结论都回链到路径、命令或用户材料。无法回链就改为 `[推测]` 或 `[未知]`。

## 安全边界

只读取结构性资料：配置样例、变量名、schema、容器和秘密管理引用。不要打开或回显 `.env`、私钥、令牌、生产数据导出或包含值的错误日志。发现可疑秘密时，记录位置类别和最小安全动作，不记录值。

## 协作交接

交接给实施者时，优先交付：最小入口/调用链、契约和数据边界、可运行或未运行的测试命令、风险热区、仍未知项和按价值排序的下一步。完整结构见 `templates.md`，检查标准见 `checklists.md`，三种使用方式见 `examples.md`。
