# 干系人汇报检查清单

## 输入与受众

- [ ] 已记录受众、渠道、可见权限、周期、范围和发送截止。
- [ ] 已写明这份更新的决策目的：知会、请求决定、解除阻塞、协调依赖或风险升级。
- [ ] 原始笔记、指标、会议记录、工单或具名提供者已进入 `F-*` 事实账本。
- [ ] 每项 `F-*` 有来源、观察日期、范围和高/中/低置信度；无法定位的说法是 `GAP-*`。
- [ ] 敏感客户、人员、安全、财务、合同或未公开信息的共享范围已确认；未确认时使用受限草稿或脱敏汇总。

## RAG 与证据边界

- [ ] 绿状态有全部关键里程碑按承诺推进的事实，没有已触发高影响风险、Blocker 或错过关键日期。
- [ ] 黄状态有具体的潜在影响、缓解、单一 owner、截止和升级路径，且没有任何红色条件。
- [ ] 红状态已明确写出错过关键日期、Blocker、实际/高确定性伤害，或缺失的决定者/owner/日期；未被其他完成项抵消。
- [ ] 缺少来源、基线、触发或权限时使用“待确认”，没有凭感觉选择颜色。
- [ ] 状态规则和对应 `F-*` 证据在摘要中可找到。

## 内容与推理

- [ ] `[事实 F-*]`、`[解释 I-*]`、`[预测 P-*]`、`[请求 A-*]` 和 `GAP-*` 分开，且解释/预测不会伪装成事实。
- [ ] 每项解释有依据与置信度；每项预测有前提、时间窗和复核点。
- [ ] 已将活动翻译为业务/用户影响；不能证明影响时写“影响待验证”。
- [ ] 每个高影响风险写明触发器、影响、缓解、单一 owner、截止、升级对象和所需决定。
- [ ] 每条决策日志有选择/选项、理由、决定者、日期和状态；推荐与最终决定没有混淆。
- [ ] 每项行动只有一个 accountable owner 和一个日期或明确事件截止；协作方没有替代 owner。

## 渠道、权限与坏消息

- [ ] 邮件、Slack、会议材料或文档的篇幅与顺序符合受众：先状态、影响、请求，再细节。
- [ ] 公开或广泛渠道没有泄露 need-to-know 之外的细节；受限信息有脱敏、受限链接或不分发处理。
- [ ] 延期、坏指标、Blocker、未知和风险没有被写成“顺利”“可控”“已解决”或绿色。
- [ ] 如有人要求粉饰，已明确拒绝改写事实，并提供真实但更清晰、分层或脱敏的版本。

## 最终判定

- [ ] **通过**：状态规则、事实边界、影响、风险、决策、单一 owner/截止和权限边界完整，可直接发送。
- [ ] **有条件通过**：可发送受限或待确认版本，且 `GAP-*`、补充 owner 和补充截止已显著展示。
- [ ] **不通过**：受众/权限/决策目的不清，RAG 缺乏关键事实，风险无 owner/日期，或仍含粉饰/敏感信息问题；先补充或升级。
