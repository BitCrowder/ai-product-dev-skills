# 干系人汇报模板

`<...>` 为需填写字段；没有来源、owner 或权限时不要猜测，使用 `GAP-*` 并保留待确认。每个行动项和风险只能有一个 accountable owner。

## 1. 沟通卡与事实账本

```markdown
# 沟通卡：<项目/主题> - <周期>
- 受众/渠道：<老板周报邮件 / 跨团队风险 Slack+文档 / 会议材料>
- 可共享范围：<公开 / 内部 / 受限；脱敏或受限链接规则>
- 决策目的：<知会 / 需要决定 / 解除阻塞 / 协调依赖>
- 需要回应者与截止：<姓名/角色；ISO 日期或明确事件>
- RAG：<绿/黄/红/待确认>；规则与证据：<F-*、里程碑、触发器>

| 类型 | ID | 内容 | 来源与观察日期 | 置信度 | 影响/前提 | 可共享范围 |
|---|---|---|---|---|---|---|
| 事实 | F-01 | <已发生、可核验的事实> | <指标/工单/会议记录；YYYY-MM-DD> | 高 | <范围> | 内部 |
| 解释 | I-01 | <对 F-* 的推断> | <依据 F-01> | 中 | <替代解释/待验证> | 内部 |
| 预测 | P-01 | <尚未发生的结果> | <依据 F-* / I-*> | 低 | <前提、时间窗、复核点> | 受限 |
| 请求 | A-01 | <希望谁决定/支持什么> | <F-* / 风险 ID> | 高 | <不行动后果> | 内部 |
| 缺口 | GAP-01 | <缺少的事实或权限> | <待提供者> | 不适用 | <对状态/决定的影响> | 内部 |
```

## 事实、解释与预测

## 4. 决策记录（单独发送或附录）

```markdown
# 决策记录：<主题>
- 决策目的与范围：<本次决定解决什么；不决定什么>。
- 事实边界：<F-*；来源；置信度>。
- 选项：<A / B / 延后 / 不行动>。
- 推荐：<I-*；理由、风险和前提>。
- 最终选择：<选择；与推荐相同/不同>。
- 决定者：<姓名/角色>；决定日期：<YYYY-MM-DD>。
- 复核触发与日期：<指标、事件或日期>。
- 后续行动：<A-*；单一 owner；截止；完成证据>。
```

## 5. 粉饰请求的安全回应

```markdown
我不能把已知延期、Blocker、坏指标或未确认信息改写成“进展顺利”。我可以把更新压缩为适合 <受众/渠道> 的结构：先说明状态和影响，再列缓解、单一 owner、截止以及需要的决定；敏感细节会放在 <受限渠道/链接>。当前需要保留的事实是 <F-* 或 GAP-*>。
```
