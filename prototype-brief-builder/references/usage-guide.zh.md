# 原型说明生成器使用说明

## 何时调用

当需要把已知产品意图转成可测试原型、Figma 交接或可运行实现说明时调用。先确认原型要改变的决定，再选择保真度；不要把“做得像产品”当成目的。

## 最小调用顺序

1. 给出目的、目标用户、核心任务、接收方和平台；有 PRD 时同时给出范围、验收、埋点和非目标。
2. 指明要验证、评审或实现什么，并说明失败后会影响什么决定。
3. 要求先输出决策卡、保真度理由和关键任务流，再展开页面、状态、组件和内容。
4. 选择接收方包：设计师、Figma、编程代理或一句话想法探索卡。
5. 用 `checklists.md` 检查状态、真实内容、响应式、无障碍、埋点和交接缺口。

## 目的到保真度的快速选择

| 你要回答的问题 | 选择 | 交付重点 |
|---|---|---|
| 用户是否理解问题、信息或流程 | 低保真探索 | 任务假设、信息层级、最小分支、未知项 |
| 用户能否完成关键任务并从错误恢复 | 中保真可用性原型 | 可点击路径、可读内容、状态、观察点、Figma 连接 |
| 关键界面是否符合品牌、密度和视觉预期 | 中到高保真评审 | 关键布局、内容密度、组件和视觉状态 |
| 代理或工程要实现已确认体验 | 高保真实现说明 | 数据、组件状态、响应式、无障碍、埋点、验收 |

## 三类交接包

### 设计师

提供研究问题、受试任务、场景、不引导的任务文案、可点击路径、页面理由、状态优先级和观察点；同时提供可记录完成/放弃、错误、犹豫点、原话和时间的观察记录格式。

### Figma

提供页面树、页面/图层命名、原型起点、组件/变体/变量、内容样式和使用边界；明确原型连接、分支、返回路径、覆盖层/焦点处理和评审注释。Figma 交接不代替设计师的研究任务与观察记录。

### Codex 或其他编程代理

提供路由/页面、组件和状态转换、数据字段与内容来源、允许/禁止的假设、响应式、语义/键盘/读屏规则、事件属性、技术约束和验收。对每个可交互行为写 `B-*` 契约，并从 `P-*`/`C-*` 追溯：当前状态、事件、守卫、下一状态、明确路由目标、副作用、接口请求、成功响应、失败响应和失败恢复。未确认的接口、权限、价格或错误恢复必须标为缺口。

### 一句话想法

只输出探索卡：候选用户与任务、最小假设流、低保真范围、未知项和补数动作。未拿到用户、平台、成功条件、内容和风险前，不输出完整页面库或高保真实现提示。

## 真实内容规则

- 优先用获授权、脱敏的真实样本；不能使用时，按真实字段、格式、长度、空值、地区和权限差异合成。
- 记录内容来源、负责人、可替换范围和敏感字段；不要把自由文本、个人身份或金额放入埋点。
- 用边界样本验证长标题、无记录、权限缺失、延迟和部分数据，避免只展示顺利的短内容。

## 交付前复核

确认每个页面有存在理由，每个关键动作有反馈和恢复，保真度与目的相称。再核对跨端任务、键盘/读屏路径、事件与隐私边界，并把未知项和补数动作留在交接物中。
