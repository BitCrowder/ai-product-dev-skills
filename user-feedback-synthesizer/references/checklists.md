# 用户反馈综合检查清单

## 范围与来源

- 已写明要支持的决定、产品区域/版本、反馈单位、时间窗、纳入/排除规则和目标分群；缺失项标为 `[未知]`。
- 每条纳入材料都有原始记录编号、渠道、时间、匿名作者/账户（若可用）、分群/版本和可定位摘录。
- 已报告原始记录数、去重反馈事件数、可识别独立用户数及各自分母；没有把它们混成“反馈数”。
- 已报告渠道构成、样本范围、未覆盖分群和渠道偏差；没有将支持、评论、销售、员工或便利样本说成总体用户。
- 引文已匿名化，且访问、保留和分享符合所给限制。

## 去重与编码

- 去重依据稳定标识、关联工单/会话、同一事件、内容和时间窗；每个合并或疑似重复都有理由。
- 同一事故的多个独立用户经历没有被误合并；无法确认的相似记录仍保留为待核。
- 已有带纳入/排除条件、反例和版本记录的编码本；代码含义变更没有覆盖旧记录。
- 每条编码记录都填写编码者/适用规则，以及高/中/低的编码置信度和依据；置信度只表示分类把握，不被当作频率、严重性或优先级。
- 方案请求与问题、期望结果、情境、当前做法和影响分开编码；没有将功能名直接当需求主题。
- 每个重要结论可回到原始记录编号、原文/摘录、代码、分群、渠道和时间。

## 主题、频率与严重性

- 主题先按分群、情境、版本、渠道和时间分析，再讨论跨群模式；未覆盖分群未被解释为“没有问题”。
- 频率写明去重事件或独立用户的分子/分母、渠道和时间窗；不把混合渠道计数写成总体比例。
- 严重性有任务阻塞、损失、风险、返工或替代成本等证据；没有影响证据时标“未评估”。
- 频率与严重性分列，没有未经认可的权重、战略、成本、可行性和风险输入就生成优先级总分。
- 支持证据、反例、矛盾、无法归类项和解释它们所需的补样均被保留；多数声音没有覆盖冲突。

## 洞察、假设与交付

- 主题、有限洞察、问题假设和候选方案分开书写；用户表达、可观察行为、研究者编码、推断和未知项未混写。
- 每项候选机会有适用分群、证据范围、替代解释、下一步验证和通过/停止条件。
- 没有把少量材料、单一引文、高声量客户、用户方案或最高频主题写成已验证需求、总体事实或路线图承诺。
- 路线图建议仅在明确补齐战略目标、影响、成本、可行性、风险、依赖和验证输入后转交 `roadmap-prioritizer`；否则只交付待验证候选机会。
- 输出明确列出可立即缓解的风险、待验证事项、不能据此断言的范围与下一步负责人/截止时间。
