# 风险驱动测试检查清单

## 输入与边界

- [ ] 行为有调用方、前置、动作、可观察结果和成功对照，且每项标为 `B-*`。
- [ ] 验收、代码、Bug、契约和现有测试约定的来源已记录；未提供信息没有被补造。
- [ ] 风险已包含影响、敏感性/频率、可恢复性和受影响边界，而非只有“需要更多覆盖”。
- [ ] 非目标、运行限制、数据/隐私边界和停止条件明确。
- [ ] `[推断]` 写明依据与验证动作；`[未知]` 写明阻断的决定。

## 测试层级与风险覆盖

- [ ] 每个 `R-*` 有最低有效层级、上移/不上移理由和稳定断言。
- [ ] 已判断边界/空状态、错误、权限、并发或幂等、契约兼容；不适用项有机制依据。
- [ ] 单元测试验证规则和状态转换，集成测试验证真实协作边界，契约测试验证协议，E2E 仅保护关键旅程。
- [ ] 没有把覆盖率百分比、快照数量、浅层 render 或 mock 调用次数作为风险已覆盖的结论。
- [ ] 快照若存在，服务于受审查的稳定契约，并配有行为断言；没有大而无语义的整页快照。

## Fixture、mock 与断言

- [ ] fixture 只包含触发行为的最小领域关系和成功对照，可重放、隔离并清理副作用。
- [ ] 时钟、随机数、队列和外部依赖可控制，或不稳定风险已记录。
- [ ] 每个 mock 标明替换的边界、保留的真实责任、无法证明的内容和契约/集成替代验证。
- [ ] mock 没有返回被测模块应计算的结果，也没有短路认证、校验、重试或错误映射。
- [ ] 断言公开响应、语义、业务状态、稳定事件或协议，不耦合私有实现、样式、树结构或偶然顺序。

## Bug 回归与证据

- [ ] 每个 Bug 回归先有 `RED-*`：修复前版本/环境、完整命令、非零退出码和原始症状失败信号。
- [ ] `RED-*` 失败不是 fixture、依赖、语法或环境错误；这些错误修复后已重新执行。
- [ ] 每个 `GREEN-*` 回链 `RED-*`，并覆盖根因不变量与一个未受影响成功对照。
- [ ] 不能红灯时有 `ALT-*`：可核查工件、阻断原因、局限及恢复 `RED-*` 的条件；结论未被误写为已证明回归。
- [ ] `T-*` 记录工作目录、完整命令或动作、执行时间、退出码、关键输出和证据位置。

## 交接判定

- [ ] 测试矩阵、fixture/mock 边界、用例、证据账本和缺口均完整可审查。
- [ ] 未运行、失败、外部契约和人工验证没有被隐藏，均有 owner 和下一步。
- [ ] **通过：** 高风险 `R-*` 有合适层级与真实 `GREEN-*`/`T-*` 证据，无未处理阻塞缺口。
- [ ] **有条件通过：** `ALT-*`、外部环境或非关键缺口存在，影响、缓解、owner 和恢复条件已接受。
- [ ] **不通过：** 行为/风险不明、关键风险只靠浅层覆盖、Bug 没有有效红灯证明，或命令证据缺失。
