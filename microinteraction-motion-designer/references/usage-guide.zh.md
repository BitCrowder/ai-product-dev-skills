# 微动效设计器使用说明

## 何时调用

当主流程和状态已清楚，需要把“更有反馈”“切换更自然”“拖拽更连续”变成可实现的动效契约时调用。先说明用户要理解什么，再决定是否需要动效；不要先选炫技模式。

## 最小调用顺序

1. 给出组件/流程、用户任务、当前和目标状态、触发、平台、技术栈及高频程度。
2. 选择反馈、连续性、层级、进度或状态变化这一项意图，并指出同级、下级、覆盖层或直接操控的空间关系。
3. 要求先输出 `M-*` 状态转换和参数表，再选择模式；手势必须补齐边界、snap point、速度单位和 `pointercancel`。
4. 同时指定完整、减少动态和低端三档；没有设备信息时以保守的 transform/opacity 基线和 `[待确认]` 交付。
5. 使用 `checklists.md` 验收快速操作、取消、焦点/读屏、性能和视觉稳定性。

## 三种常见入口

| 请求 | 正确起点 | 不应直接做 |
|---|---|---|
| 优化列表进入 | 只定义首屏可见项、扫描顺序和首次播放 | 让所有列表、回访和滚动追加逐项进场 |
| 给全页加高级动效 | 选一个高频任务和一处层级关系试点 | 默认添加视差、blur、stagger 和无限动画 |
| 低端与减少动态 | 定义等价状态信息和可测降级条件 | 仅把动画 `display: none` 后忽略反馈 |

## 与其他 Skill 串联

- 从 `prototype-brief-builder` 接收页面、状态、任务流、响应式和无障碍边界；状态缺失时退回补齐，而不是发明动画。
- 将已确认的 `M-*` 契约交给 `spec-to-implementation-plan` 拆成代码任务，交给 `test-generator` 覆盖快速切换、取消和三档行为。
- 交给 `code-review-assistant` 时附上参数、性能信号、减少动态行为和视觉/交互测试证据。

## 交付前复核

确认每段动效都有目的和空间语义，每个参数都有数值与单位，每个中断都有状态/清理规则。再确认减少动态和低端档仍保留任务、状态和恢复路径，最后才审美化细节。
