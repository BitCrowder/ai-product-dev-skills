# 路线图优先级排序器使用说明

## 何时调用

当团队需要在有限周期和容量内取舍候选项时调用。先说明要支持的决定，例如“决定下季度是否把企业能力放在增长功能之前”，而不是只要求“给需求排序”。

## 最小输入包

不知道的项写 `[未知]`：

```text
决定、决策人、规划周期、目标指标、护栏和不可触碰限制：
候选项的用户问题、预期结果、负责人和已有证据（来源/日期）：
Reach、Impact、Confidence、Effort 的单位、时间窗、来源和估算范围：
可用角色容量、维护/已承诺工作、外部截止时间和依赖：
战略、合规、合同或安全强制项的指定人、依据、最小范围和失败后果：
```

## 推荐调用方式

```text
Use $roadmap-prioritizer：为本季度做路线图决定。先选择适合现有证据的模型；显示公式、尺度、单位、证据置信度和未知项；分开强制项、依赖、角色容量与敏感性分析；最后分别给出评分、推荐组合和具名最终决定。
```

## 三类输入如何处理

- **完整 RICE：** 先检查 Reach 的同一时间窗、Impact 锚点、Confidence 证据和跨职能 Effort；随后用容量和关键路径形成阶段组合，而非机械按分数排序。
- **早期 ICE：** Impact、Confidence、Ease 各自只能按 `1-5` 的目标影响、证据和交付摩擦锚点评分；它们不复用 RICE 的比例/百分比，Ease 也不等同 Effort。任一项不能匹配锚点时保持 `[未知]`。
- **主观清单：** 不编数字。将其变成问题假设、证据账本和补数计划；没有能匹配 ICE 锚点的事实时也不填 ICE。可先用 MoSCoW 协商范围，直到能做可信比较。
- **指定优先级：** 将可核验的战略、合规、合同或安全要求登记为强制项；记录其容量占用和机会成本。没有指定人和依据的要求只是偏好。

## 如何解读结果

- 分数是模型在给定假设下的比较结果；它不证明结果会发生，也不构成工程或业务承诺。
- 推荐组合已经考虑容量、角色、依赖、风险和学习价值；最终决定可偏离推荐，但必须有具名理由和重审条件。
- `[未知]`、低置信度或敏感排序意味着需要研究、测量、小范围验证或工程确认，不意味着该项价值为零。

完整字段见 `templates.md`，交付前使用 `checklists.md`，三种输入的闭环示例见 `examples.md`。
